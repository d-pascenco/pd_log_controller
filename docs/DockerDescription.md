## Установка и настройка docker

PS: на текущем сервере у нас подман. Podman — более новый инструмент от Red Hat, 
сделанный как альтернатива Docker. Команды те же, просто заменяем `docker` на `podman`.

### 1. Основные функции
- FROM — базовый образ.
Пример: `FROM python:3.14.5`
Это первая инструкция; без неё Dockerfile не соберётся.


- WORKDIR — рабочая директория внутри образа.
Пример: `WORKDIR /app`
Это значит, что внутри контейнера создастся директория /app и туда скопируются все файлы проекта.

- COPY — копирует файлы из контекста сборки в образ.
Пример: COPY . /app
Первый агрумент "какие файлы взять на хосте", второй аргумент "куда положить"


- ADD — как COPY, но умеет распаковывать архивы и брать URL.
Пример: `ADD app.tar.gz /app/`
Значит скопировать файл с распаковкой .tar.


- RUN — выполняет команду во время docker build.
Пример: `RUN pip install -r requirements.txt`


- CMD — команда по умолчанию при docker run; может быть переопределена аргументами запуска.
Пример: `CMD ["python", "/home/pd/pd_log_controller/app/Home.py"]`
Тут `python` — это имя команды, которое ищется в PATH внутри контейнера; а второе — это что имено запустить.
Важно, что это одна команда с аргументами. Если нужно запустить несколько разных команд,
то лучше, например, через shell (sh -c "python Home.py && node server.js & wait").


- ENTRYPOINT — основная команда контейнера, которую обычно не меняют.
Пример: `ENTRYPOINT ["python", "Home.py"]`
Это значит: контейнер всегда будет запускать это, а CMD можно использовать как дополнительные аргументы.


- EXPOSE — показывает, какой порт использует контейнер, но сам порт не публикует
Пример: `EXPOSE 8000`
Это значит: контейнер слушает порт 8000, но наружу он сам не откроется. 
Для этого нужен -p.


- ENV — переменные окружения внутри образа.
Пример: `ENV PYTHONUNBUFFERED=1`
Это значит: задать переменную, которая будет доступна внутри контейнера.

  
- ARG — переменная только для сборки.
Пример: `ARG VERSION=1.0`
Это значит: использовать значение во время docker build, но не хранить его как обычную переменную контейнера.


- VOLUME — папка для данных, которые должны сохраняться отдельно.
Пример: `VOLUME /data`
Это значит: данные в этой папке можно хранить в томе, чтобы они не пропали после удаления контейнера.
Важно, что VOLUME в Dockerfile сам по себе не задаёт конкретную папку на хосте.
Конкретный путь на хосте задают через `docker run -v /home/user/data:/data myimage` 
(слева — папка на хосте; справа — папка в контейнере.)


- USER — пользователь, от которого будут запускаться команды.
Пример: `USER appuser`
Это значит: контейнер дальше работает не от root, а от указанного пользователя.
USER appuser = "выполняй команды как этот пользователь", как если бы в Linux сделать `su appuser` перед запуском.


- HEALTHCHECK — проверка, жив ли контейнер.
Пример: `HEALTHCHECK CMD curl -f http://localhost:8000 || exit 1`
Это значит: Docker периодически проверяет, отвечает ли приложение и в `docker ps` будет пометка.


- LABEL — метка с описанием образа.
Пример: `LABEL maintainer="me@example.com".a:/data myimage`
Это значит: добавить служебную информацию, которая не влияет на запуск (будет отображаться в `docker inspect`).


- SHELL — задаёт shell для команд RUN.
Пример: `SHELL ["bash", "-c"]`
По умолчанию Docker выполняет RUN через shell, обычно через /bin/sh -c в Linux-образах.
Команда выше говорит Docker-у вместо этого использовать bash -c.


- STOPSIGNAL — сигнал остановки контейнера.
Пример: `STOPSIGNAL SIGTERM`
Это значит: какой сигнал отправлять процессу при docker stop.
Названия сигналов заранее определены в ОС/Linux.
SIGTERM — “мягко завершить”.
SIGKILL — “убить сразу”.
SIGINT — обычно Ctrl+C.
SIGSTOP — остановить выполнение.

### 2. Основные команды

`docker build -t имя:тег .` — собрать образ.
`docker run -p 8080:8000 имя:тег` — запустить контейнер и пробросить порт.
`docker ps` — показать запущенные контейнеры.
`docker ps -a` — показать все контейнеры.
`docker images` — показать образы.
`docker logs` <container> — показать логи контейнера.
`docker exec` -it <container> bash — зайти внутрь контейнера в баш. (выйти `exit`)
`docker stop` <container> — остановить контейнер.
`docker rm <container>` — удалить контейнер.
`docker rmi <image>` — удалить образ.
`docker push` отправляет образ в registry, например Docker Hub.

### 3. После docker build

Образ сохранятеся на той же машине в служебной директории, его можно увдиеть через `docker images`.

### 4. Как отправить образ куда-то 

- Собрать образ локально.
- Отправить его в registry: Docker Hub, GitHub Container Registry, GitLab Registry или приватный registry.
- На удалённом хосте сделать docker pull.
- Запускать контейнер из этого образа.

Локально:
```
docker build -t myuser/pd_log_controller:1.0 .
docker push myuser/pd_log_controller:1.0
```

На сервере:
```
docker pull myuser/pd_log_controller:1.0
docker run -d --name pd_log_controller myuser/pd_log_controller:1.0:1.0`
```

Можно использовать приватный registry, например:
```
docker tag pd_log_controller:1.0 registry.example.com/pd_log_controller:1.0
docker push registry.example.com/pd_log_controller:1.0
```

**Альтернатива для офлайн-сервера: docker save на одной машине и docker load на другой:**
- На машине A собрал образ:
```
docker build -t myapp:1.0 .
```
- Сохранил образ в файл:
```
docker save -o myapp_1.0.tar myapp:1.0
```
Это создаст обычный файл myapp_1.0.tar.
- Перенёс этот файл на сервер B, например:
```
scp myapp_1.0.tar user@server:/tmp/
```
- На сервере B загрузил образ из файла:
```
docker load -i /tmp/myapp_1.0.tar
```
После этого образ появится в docker images.
- Запустил контейнер:
```
docker run -d --name myapp myapp:1.0
```

### 5. Аргументы `docker run`

- `-p host:container` — проброс порта.
  Пример: `-p 8080:8000`.
  Используется, когда сервис внутри контейнера слушает порт, и его надо открыть на хосте.


- `-d` — запуск в фоне.
  Пример: `docker run -d ...`.
  Используется для серверов, чтобы терминал сразу освободился.


- `--name` — имя контейнера.
  Пример: `--name app1`.
  Используется, чтобы удобно ссылаться на контейнер в `docker logs`, `docker stop`, `docker exec`.


- `-it` — интерактивный режим + терминал.
  Пример: `docker run -it ubuntu bash`.
  Используется для входа в shell, отладки, ручных команд.


- `-e KEY=value` — переменные окружения.
  Пример: `-e DB_HOST=postgres`.
  Используется для передачи настроек приложению.


- `-v host:container` — том или bind mount.
  Пример: `-v ./data:/data`.
  Используется для данных, логов, конфигов, чтобы они жили вне контейнера.


- `--rm` — удалить контейнер после остановки.
  Пример: `docker run --rm ...`.
  Используется для временных контейнеров и тестов.


- `--restart` — политика перезапуска.
  Пример: `--restart unless-stopped`.
  Используется для сервисов, которые должны подниматься после падения или перезагрузки.


- `--network` — выбор сети.
  Пример: `--network mynet`.
  Используется, когда контейнеры должны видеть друг друга по именам.


- `-w`, `--workdir` — рабочая директория внутри контейнера.
  Пример: `-w /app`.
  Используется, чтобы не писать полный путь в командах.


- `-u`, `--user` — пользователь запуска.
  Пример: `-u 1000:1000`.
  Используется для безопасности и прав на файлы.


- `--entrypoint` — переопределить `ENTRYPOINT` образа.
  Пример: `--entrypoint sh`.
  Используется для отладки, когда надо запустить другую команду.


- `-m`, `--memory` — лимит памяти.
  Пример: `-m 512m`.
  Используется для ограничения ресурсов контейнера.


- `--cpus` — лимит CPU.
  Пример: `--cpus 1.5`.
  Используется для ограничения процессорного времени.

### 6. .dockeringnore

**.dockerignore** — это файл, который говорит Docker, 
что не отправлять в build context при docker build (т.е. список правил игнора).
Нужен, чтобы ускорить сборку (не тащить лишние файлы), уменьшить размер контекста сборки, 
не дать случайно упаковать секреты, логи, кэш, .venv, .git и т.д.
Должен лежать в корне контекста сборки (рядом с Dockerfile).


**Как работает (пример):**
```text
.venv
.git
__pycache__
*.pyc
.env
logs
```

**Синтаксис:**
`#` — комментарий.
`name` — игнорировать файл/папку с таким именем.
`*.log` — игнорировать все .log.
`**` — матчить любое число вложенных папок.
`!file` — исключение, вернуть файл обратно из игнора.

.dockerignore влияет на контекст сборки, а не на уже запущенный контейнер.
Если файла нет, Docker может отправить в сборку вообще всё из папки проекта.

### 7. docker-compose

docker-compose — способ описать несколько сервисов (контейнеров) в одном файле
и поднять их одной командой. Без него пришлось бы для каждого сервиса 
вручную писать `docker run` с кучей аргументов.

Файл `docker-compose.yml` лежит в корне проекта.

**Структура файла:**
```yaml
services:
  имя_сервиса:
    build: .              # путь к Dockerfile (точка = текущая папка)
    command: ...          # переопределяет CMD из Dockerfile
    ports:
      - "хост:контейнер"  # проброс портов
    restart: unless-stopped
```

`build: .` — говорит docker-compose: "собери образ из Dockerfile в текущей папке".
`command:` — переопределяет CMD из Dockerfile. Удобно, когда один образ,
но разные сервисы запускают разные команды.
`restart: unless-stopped` — перезапускать контейнер, если упал, кроме случая ручной остановки.

**Несколько сервисов из одного образа:**

Если в проекте один Dockerfile, но нужно запустить и бэкенд, и фронтенд —
в docker-compose просто делаем два сервиса с разными `command:`.
Dockerfile в таком случае не содержит CMD, потому что команду задаёт docker-compose.

Пример для нашего проекта:
```yaml
services:
  backend:
    build: .
    command: uvicorn src.api.main:app --host 0.0.0.0 --port 8000
    ports:
      - "8000:8000"
    restart: unless-stopped

  frontend:
    build: .
    command: streamlit run app/Home.py --server.address=0.0.0.0 --server.port=8501
    ports:
      - "8501:8501"
    restart: unless-stopped
```

**Основные команды docker-compose:**
`docker compose up --build` — собрать образы и запустить все сервисы.
`docker compose up -d --build` — то же самое, но в фоне.
`docker compose logs -f` — смотреть логи всех сервисов.
`docker compose logs -f backend` — логи только бэкенда.
`docker compose down` — остановить и удалить контейнеры.
`docker compose down -v` — то же + удалить тома (данные БД и т.д.).
`docker compose ps` — показать статус запущенных сервисов.
`docker compose restart backend` — перезапустить конкретный сервис.
